# 도우 소개 영상 만들기 (dou-intro-video)

영상 파일을 직접 편집하지 않고 **코드로 그린다.** 컷 하나가 장면 파일 하나이고, 장면 파일은 "t초에 화면이 어떻게 생겼는지"를 그림(SVG)으로 돌려준다. 브라우저가 1/30초마다 그 그림을 찍고 ffmpeg가 mp4로 묶는다. 효과음은 컷마다 "몇 초에 무슨 소리"를 적은 큐 시트에서, 음악은 코드에서 만든다. 그래서 문구·시각·그림을 고치고 명령 한 줄로 다시 뽑을 수 있다.

기준 결과물은 새록(81~102초)·미리봄(88~110초) 부스 영상이다. 이 영상들의 품질은 엔진이 아니라 **수십 번의 피드백으로 다듬은 기준**에서 나왔다. 그 기준이 `references/`에 있고, 이 스킬의 핵심은 그것을 처음부터 지키는 것이다.

## 진행 체크리스트

할 일 목록으로 만들고, 사용자 확인을 기다리는 경우가 아니면 열린 항목을 남긴 채 턴을 끝내지 않는다.

- [ ] 0 준비 — 제작 틀 받기·설치, README·DIRECTION 읽기
- [ ] 1 브리프 — `references/brief.md`. 사용자 확인
- [ ] 2 컷 구성(스토리보드) — `new-video.js`로 시작, 컷 표로 사용자 확인
- [ ] 3 실제 앱 화면 캡처 확보
- [ ] 4 장면 구현 — 컷마다 `references/quality-bar.md` 기준
- [ ] 5 효과음·음악 — `references/sound.md`
- [ ] 6 정지 화면 자가 검수 — `references/review-checklist.md`
- [ ] 7 실시간 미리보기로 사용자 검토 → 반복
- [ ] 8 속도 점검(처음 보는 사람 기준)
- [ ] 9 검토본 mp4 → 사용자 확인
- [ ] 10 "저장해"를 들은 뒤에만 확정본·커밋

## 0. 준비

제작 틀은 비공개 리포 `douinc/booth-design`의 `intro-video/` 폴더다. douinc 조직 권한이 필요하다.

```bash
gh repo clone douinc/booth-design        # 이미 있으면 git pull
cd booth-design && git switch -c video/<영상 id>
cd intro-video
bun install && bunx playwright install chromium     # 또는 npm install && npx playwright install chromium
tools/audio/setup.sh                                 # 효과음 뱅크(earshot)·파이썬 도구 — 처음 한 번
```

필요한 것: Node 20 이상(또는 Bun), ffmpeg, Python 3.10 이상, git. 없으면 무엇을 깔아야 하는지 사용자에게 쉬운 말로 알린다.

**록스타가 최신 디자인인지 확인한다.** 록스타의 움직임(뼈대 엔진)과 눈 모양은 디자인 리포 `douinc/saylog-design`에서 복사해 온 것이라, 그쪽에서 바뀌어도 영상에는 저절로 들어오지 않는다. `tools/rig/entry.ts` 머리 주석의 커밋과 saylog-design의 `app/shared/logstar/`·`app/shared/saylog-star.tsx` 최근 커밋(`git log -3 -- <경로>`)을 비교해, 더 새것이 있으면 `jelly.ts`·`skeleton.ts`를 다시 복사하고(영상용 `case "float"` 한 줄은 다시 넣는다) `bun run rig`, 눈 모양은 `lib/prims.js`의 `EYES`에 옮긴다. 바꾼 뒤 정지 화면으로 도는 순간과 웃는 눈을 확인한다.

**시작 전에 `intro-video/README.md`(장면 파일 규약·명령어)와 `DIRECTION.md`(v3 연출 규약)를 읽는다.** 그림 도구(`P.*`)·움직임 도구(`A.*`)·록스타(`L.star`)의 쓰는 법은 거기와 `lib/*.js` 머리 주석에 있다. 이 스킬은 그 문서를 되풀이하지 않고, 그 위에 작업 순서와 품질 기준을 얹는다.

## 1. 브리프

`references/brief.md`의 칸을 채운다. 요청에 없는 칸은 한 번에 묻고 칸마다 추천값을 붙인다. **문구·숫자·QR 주소·고객명에는 기본값이 없다** — 원천(기획서, 앱 화면, 사용자 말)이 있는 것만 쓴다. 확정 요약을 보여 주고 확인을 받는다.

## 2. 컷 구성

```bash
node tools/new-video.js <영상 id> <이름>     # 예: node tools/new-video.js yakmeokja 약먹자
```

스토리보드(`data/storyboard.js`)에 영상이 더해지고 큐 시트와 장면 셋(제목 · 제품 화면 · 엔딩)이 생긴다. **서비스 아이콘은 영상 id로 자동으로 들어간다**(`P.serviceIcon` — `saylog` · `miribom` · `yakmeokja` · `subal`). 그래서 id는 서비스 영문 이름으로 짓는다. 로고를 직접 그리거나 웹에서 받아 쓰지 않는다. 목록에 없는 새 서비스는 공식 SVG를 사용자에게 받아 `assets/img/logos/`에 넣고 `LOGO_FILES`에 이름을 더한다. 이 셋은 검증된 짜임새의 축소판이라 그대로 돌아간다. 여기서 브리프의 흐름대로 컷을 늘린다. 컷마다 `vo`(한 줄 문장 = 자막), `visual`(화면), `motion`(사건과 시각), `sfx`(소리 계획), `cut`(다음 컷으로 넘어가는 동작)을 적는다.

검증된 흐름은 이렇다. 브리프에 맞게 고르되, 처음 보는 사람이 "왜 필요한지 → 무엇인지 → 어떻게 되는지 → 어디서 받는지" 순서로 따라오게 한다.

| 자리 | 하는 일 | 예시 |
|---|---|---|
| 훅 | 현장의 불편을 타이포 모션으로(사람 그림 없이) | 새록 1 · 미리봄 1 |
| 록스타 등장 | 캐릭터가 불편 더미에서 튀어나옴 | 새록 2 · 미리봄 2 |
| 제목 | 파란 바탕, 한 줄 메시지 + 브랜드 낱말 | 새록 3 · 미리봄 3 |
| 제품 컷 4~8개 | 한 컷에 기능 하나. 실제 화면으로 전→후 | 새록 4~12 |
| 요약 | 한 줄로 다시 | 새록 13 |
| 엔딩 | 앱 아이콘·이름·한 줄 소개·QR·dou | 새록 14 · 미리봄 13 |

컷 표(번호 · 시각 · 자막 문장 · 화면 · 움직임)를 사용자에게 보여 주고 확인을 받은 뒤 장면을 짠다. 흐름·범위를 바꾸는 결정은 사용자 몫이다.

## 3. 실제 앱 화면

제품 컷의 화면은 **실제 앱 캡처**다. 손으로 다시 그린 앱 화면은 "프레임이 이상하다"는 피드백을 받았다.

- 캡처 원천: 디자인 리포(예: saylog-design)의 프로토타입을 Playwright로 찍거나, 사용자가 준 스크린샷. 확대해도 깨지지 않게 2배 해상도 이상.
- 화면 속 이름·번호는 자리표시만(테스터1, 010-0000-0000, E9999001). 실명·실제 환자 자료는 쓰지 않는다.
- `assets/screens/<id>/`에 넣고 `manifest.json`에 `{file, cssW, cssH, state}`를 적은 뒤 `node tools/screens.js`.
- 내레이션·받아쓰기·서식 내용은 **캡처 속 내용과 맞아야 한다**(혈액 검사표 사진이면 받아쓰기도 혈액 검사 이야기). 안 맞으면 캡처를 다시 찍는다.
- 없는 화면은 사용자에게 알리고, 실제 앱 모양을 따라 그린다(미리봄 7·8·11컷 방식).

## 4. 장면 구현

`scenes/<id>/sNN.js` 한 파일이 한 컷이다. README의 "장면 파일 계약"을 지키고(320×180 좌표, 자막 영역 y≥156 비움, `Date`·`Math.random` 금지, 색은 `P.*` 토큰만), 그림·움직임은 `references/quality-bar.md`를 따른다.

- 새 컷을 짜기 전에 비슷한 기존 컷을 먼저 연다. 아래 표가 출발점이다.
- 장면 파일 머리 주석에 그 컷의 **큐(로컬 시각)와 구도**를 적는다. 기존 파일이 다 그렇게 되어 있고, 다음 사람이 고칠 때 이걸 본다.
- 큐 시트가 시각의 기준이다. 화면 사건(탭·결과·등장)은 큐 시각과 ±1프레임(33ms) 안에서 일어나야 소리와 맞는다.

| 만들려는 것 | 먼저 볼 파일(`scenes/`) |
|---|---|
| 타이포가 쏟아지는 훅 | `saylog/s01.js` · `miribom/s01.js` |
| 록스타 등장 | `saylog/s02.js` |
| 제목 | `saylog/s03.js` |
| 폰 화면에서 탭 → 다음 화면 | `saylog/s04.js` · `saylog/s05.js` |
| 실시간으로 채워지는 결과 + 완료 순간 록스타 | `saylog/s06.js` |
| 워치 · 데스크탑 창 · 노트북 | `saylog/s09.js` · `saylog/s10.js` · `miribom/s11.js` |
| 기기 두 대를 잇기 | `miribom/s12.js` |
| 엔딩 카드(아이콘·QR·dou) | `saylog/s14.js` · `miribom/s13.js` |

## 5. 효과음·음악

`references/sound.md`. 큐 시트(`data/cues.<id>.json`)를 장면과 함께 고친다. 소리를 만들 때마다 `mix.py` 출력의 `missing`이 비어 있는지 본다.

## 6. 정지 화면 자가 검수

**사용자에게 보여 주기 전에 직접 본다.** 코드가 오류 없이 돈다고 화면이 맞는 건 아니다.

```bash
node tools/stills.js <id> <컷> --count 8                 # out/stills/<id>-NN/sheet.png
node tools/stills.js <id> <컷> --times 1.5,1.6,2.4,2.5   # 큐 순간 전후
node tools/strip.js <id> --step 0.5                       # 영상 전체 흐름
```

`sheet.png`를 열어 `references/review-checklist.md`로 훑는다. 걸린 것은 고치고 다시 찍는다. 같은 결함이 두 번 고쳐도 남으면 멈추고 사용자에게 보고한다.

## 7. 사용자 검토 — 실시간 미리보기

```bash
node tools/serve.js     # 한 번 띄워 두면 장면 파일을 고칠 때마다 열린 페이지가 2초 안에 새로고침된다
open "http://localhost:8790/preview.html?video=<id>&t=<초>"
```

미리보기는 mp4를 만들지 않아 바로 보인다. 잦은 수정은 여기서 보여 준다. 소리는 마지막으로 믹스한 `out/audio/<id>.wav`가 함께 재생된다.

보고는 `수정 화면 | 위치(주소·컷 번호) | 볼 것` 3열 표로 시작하고, 주소는 `open`으로 직접 띄운다. 사용자는 스크린샷과 짧은 말("여기 잘림", "너무 빨라")로 피드백한다 — 그 컷만 고치고, 같은 종류의 결함이 다른 컷에도 있는지 함께 본다.

## 8. 속도 점검

사용자가 매번 짚은 문제가 "처음 보는 사람이 인지하기 전에 넘어간다"였다. 장면이 다 되면 **처음 보는 사람이 되어** 컷마다 묻는다: 어디를 누르는지 보이는가, 결과를 읽을 시간이 있는가, 자막을 다 읽을 수 있는가. 기준 숫자는 `references/quality-bar.md` "속도". 늘릴 때는 장면을 다시 짜지 말고:

```bash
node tools/retime.js <id> '{"4":{"slow":1.25},"6":{"hold":0.5}}'   # 컷을 1.25배로 늘리고, 끝에서 0.5초 더 머묾 — 큐 시트도 함께 옮겨진다
```

## 9. 검토본

```bash
tools/build.sh <id> --review     # out/review/<id>.mp4 — 확정본은 건드리지 않는다
open "http://localhost:8790/review.html?video=<id>"
```

1080p 렌더는 영상 1분에 10~20분쯤 걸린다. 수정할 때마다 뽑지 말고 미리보기에서 모아 고친 뒤 한 번 뽑는다. 빠른 확인은 `--fast`(720p).

## 10. 저장

사용자가 "저장해"라고 할 때만 확정본을 만들고(`tools/build.sh <id>` → `out/<id>.mp4`, 필름 스트립 `node tools/strip.js <id>`) 커밋한다. 확인 전에 확정본을 덮어쓰거나 커밋하지 않는다 — 영상은 계속 다듬는 중이라 사용자가 고른 순간이 확정이다. 커밋에는 mp4와 스트립, 바뀐 코드만 넣는다(`out/`의 나머지는 다시 만들 수 있어 무시된다).

## 하지 않는 것

- 실제 앱 화면 대신 손으로 그린 UI, 실사 사진 그대로(일러스트 톤으로 바꾼다), 생성 이미지 속 한글.
- 원천이 없는 숫자·고객명·효과("시간 50% 단축" 같은 것). `[확인 필요]`로 남기고 묻는다.
- 확인 없이 확정본 덮어쓰기·커밋·푸시·업로드.
- 공개 리포에 제작 틀 코드나 앱 캡처를 올리기. 제작 틀은 비공개 리포에만 둔다.
