# 브리프

영상을 짜기 전에 아래 칸을 채운다. 요청에 없는 칸은 **한 번에** 묻고, 칸마다 추천값과 이유를 붙인다. 사용자가 말한 값과 추론·기본값을 나눠서 확정 요약을 보여 준다.

## 칸

| 칸 | 묻는 것 | 기본값·추천 |
|---|---|---|
| 제품 | 어느 서비스, 어느 화면(앱·웹 콘솔·데스크탑·워치) | — |
| 쓰는 곳 | 부스 모니터 반복 재생, 유튜브, 영업 미팅, 소셜 | 부스 반복 재생이면 소리 없이 봐도 이해되게 자막 필수 |
| 보는 사람 | 누가 처음 보는가(의사·간호사·병원 관리자·환자) | **처음 보는 사람** 기준으로 속도를 잡는다 |
| 메시지 한 줄 | 영상이 끝나고 남길 한 문장 | 제목·엔딩에 쓰인다. 진짜 문제를 짚는지 확인(아래) |
| 길이 | 초 | 제품 컷 6~8개면 80~110초. 짧게 하려면 컷 수를 줄이지 컷을 빠르게 하지 않는다 |
| 컷 목록 | 보여 줄 기능과 순서 | 아래 "컷 한 줄 점검" 통과한 것만 |
| 사실 원천 | 기획서·앱 화면·홈페이지·사용자 말 | 원천 없는 숫자·고객명은 `[확인 필요]` |
| 실제 화면 | 컷마다 필요한 캡처 목록과 어디서 찍을지 | 디자인 리포 프로토타입, 사용자 스크린샷 |
| 엔딩 | 앱 아이콘, 한 줄 소개, QR 주소와 각 QR이 가리키는 페이지 | QR 문구는 페이지에 맞게("다운로드", "더 알아보기") |
| 내레이션 | 성우 녹음 / 자막만 | 자막만이 기본. 녹음은 나중에 `mix.py --vo`로 얹는다 |
| 말투 | 자막 문장 어미 | 짧은 명사형·해요체. 한 영상 안에서 섞지 않는다 |

## 메시지가 진짜 문제를 짚는가

새록 첫 판은 "서식 종류가 128종이나 된다"를 강조했다. 사용자가 짚은 진짜 문제는 **"서식 작성에 시간을 많이 쓴다"**였다. 그래서 첫 컷은 쏟아지는 서식 이름 옆에 계속 올라가는 작성 시간 시계를 두었다. 미리봄도 "몇 번째 작성 중"이 아니라 **시간과 대기 환자 수**를 강조했다.

메시지를 정할 때 "보는 사람이 실제로 괴로운 게 이것인가, 아니면 이것 때문에 생기는 무엇인가"를 한 번 더 묻는다. 확신이 없으면 사용자에게 두 안을 보여 준다.

## 컷 한 줄 점검

컷마다 두 줄을 적어 본다.

1. 이 컷에서 제품이 무엇을 해 주는가
2. 그래서 보는 사람은 무엇이 편해지는가

- 2번이 비면 기능 나열이다. 컷을 불편(전)으로 열고 가치(후)로 닫는다.
- 한 컷에 기능 하나. 두 개가 한 화면에 들어오면 헷갈린다(미리봄 "말로 답하기"와 "그림으로 답하기"는 결국 두 폰을 차례로 보여 주도록 나눴다).
- 흐름이 논리 순서인지 본다. "말과 사진으로"라고 말하는 컷에서 사진 화면 없이 바로 결과가 나오면 순서가 이상하다는 피드백을 받았다 — 말한 것을 먼저 보여 준다.
- 같은 강조를 두 컷에서 반복하지 않는다.
- 기기·채널 나열("워치에서도, PC에서도")은 한 컷으로 충분하다.

## 확정 요약 형식

```
영상: <이름> (<id>) · <길이>초 · 1920×1080 · 자막만
메시지: <한 줄>
보는 사람 / 쓰는 곳: …
컷: 1 훅 … / 2 … / … / N 엔딩
엔딩: 한 줄 소개 "<…>" · QR <페이지 → 문구>
확인 필요: <원천 없는 사실>
(추론·기본값: …)
```
