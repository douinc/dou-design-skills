# 검수표 — 정지 화면에서 볼 것

사용자에게 보여 주기 전에 `stills.js` 시트와 `strip.js` 스트립을 직접 열어 이 표로 훑는다. 아래는 새록·미리봄 작업에서 사용자가 실제로 짚은 결함을 많이 나온 순서로 정리한 것이다. 같은 결함은 다른 컷에도 있을 가능성이 높으니, 하나를 고치면 같은 종류를 영상 전체에서 찾는다.

## 찍는 시각

- 컷마다 고르게 8장(`--count 8`).
- 큐 순간 전후: 탭 직전·직후, 결과가 뜨는 프레임, 완료 칩.
- 전환 구간: 컷 시작 0.0 · 0.1 · 0.2 · 전환 길이 + 0.1(`--abs`로 절대 시각).
- 마지막 프레임(다음 컷이 이 프레임을 밀어낸다).

## 1. 잘림·겹침 — 가장 많이 나왔다

- [ ] 기기 바닥·노트북 받침·워치 줄이 화면 밖으로 나가거나 잘리지 않는가
- [ ] 탭 효과·강조 테두리가 기기 틀에 잘리지 않는가(필요하면 틀 밖 레이어로)
- [ ] 글자와 기기가 겹치지 않는가
- [ ] 떠 있는 버튼(녹음 버튼 등)이 맨 앞에 있는가 — 카드 뒤로 숨지 않는가
- [ ] 숫자·체크박스·체크 아이콘이 칸 밖으로 나가거나 어긋나지 않는가
- [ ] 자막 영역(y ≥ 156)이 비어 있는가

## 2. 강조 모양

- [ ] 강조 테두리가 짚는 요소에 정확히 맞는가(어긋남 없음)
- [ ] 모서리가 동심인가 — 요소 반지름 + 띄운 만큼, 끝이 찌그러지지 않음
- [ ] 칩·알약 좌우 여백이 같고 과하지 않은가(오른쪽만 넓은 경우가 잦았다)
- [ ] 색 강조가 의미 있는 낱말에 가 있는가

## 3. 구도

- [ ] 전체가 한쪽으로 쏠리지 않았는가 — 기기 + 설명 덩어리가 가로 가운데
- [ ] 기기와 설명 글 사이가 너무 벌어지지 않았는가
- [ ] 두 기기를 나란히 둘 때 바닥선·이름표가 맞춰져 있는가
- [ ] 한 화면에 이야기가 하나인가(이미지 두 장이 경쟁하지 않는가)

## 4. 그림 품질

- [ ] 그림자가 겹치지 않는가(PNG 안 그림자 + 넣은 그림자, 바닥 그림자 둘)
- [ ] 확대된 캡처가 깨지지 않는가
- [ ] 실물 사진이 튀지 않는가 — 일러스트 톤
- [ ] 외곽선이 너무 진하지 않은가
- [ ] 어두운 덮개가 상태 표시줄까지 덮는가
- [ ] 한글 자간이 고른가, 글꼴이 대체 글꼴로 바뀌지 않았는가

## 5. 내용

- [ ] 화면 속 내용과 자막·받아쓰기·결과 내용이 같은 이야기인가
- [ ] 같은 강조가 두 번 나오지 않는가
- [ ] 흐름이 말한 순서대로인가(말한 것을 먼저 보여 준다)
- [ ] 실명·실제 환자 정보가 없는가
- [ ] 원천 없는 숫자가 없는가

## 6. 움직임(스트립·미리보기에서)

- [ ] 0.3초 넘게 빈 화면이 없는가(전환 포함)
- [ ] 같은 기기가 컷을 넘어갈 때 크기·자리가 튀지 않는가
- [ ] 흐르는 시계·카운터가 컷 경계에서 멈추지 않는가
- [ ] 누름 → 결과 → 다음 동작 사이에 인지할 시간이 있는가(`quality-bar.md` "속도" 표)
- [ ] 제품 컷에서 록스타가 화면 읽기를 방해하지 않는가
- [ ] 첫 프레임에 이상한 조각(록스타 눈만 먼저 보임 등)이 없는가
- [ ] 반투명으로 탁해지는 요소가 없는가

## 7. 소리(`sheet.py` 점검판 + 미리보기)

- [ ] `missing`이 비어 있다
- [ ] 큐 선이 화면 사건 프레임에 있다
- [ ] 연속 소리의 음정이 올라간다
- [ ] 마지막 코드가 엔딩 착지 프레임에 있다, 끝 전에 소리가 끝난다

## 전문가 시선 자가 검토

사용자는 자주 "영상 디자인 전문가가 되었다고 생각하고 처음부터 끝까지 검토해 줘"라고 요청했다. 그 요청이 오기 전에 한 번 스스로 한다: 스트립 전체를 보며 (1) 처음 보는 사람이 컷마다 무엇을 봐야 할지 아는가, (2) 컷마다 화면이 깔끔하고 정돈돼 보이는가 — 어설퍼 보이는 레이아웃은 없는가, (3) 영상 전체에 색·크기·움직임의 규칙이 하나로 지켜지는가. 걸린 컷을 목록으로 만들어 고친 뒤 보여 준다.
