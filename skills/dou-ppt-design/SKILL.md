# 도우 발표자료 만들기 (dou-ppt-design)

파이썬으로 장마다 도형·글자 위치를 정의하고, 한 번에 **파워포인트 파일**과 **미리보기 화면**을 같이 뽑는 방식입니다.
모든 도형·글자가 파워포인트·구글 슬라이드에서 바로 고칠 수 있는 개체로 들어갑니다(통 이미지 아님).

사용하는 사람은 대개 개발자가 아닌 기획·디자인·영업 팀원입니다.
대화에서는 코드·개발 용어 대신 "장", "표지", "미리보기", "글이 넘침" 같은 말을 쓰고, 코드는 보여주지 않습니다.

## 폴더 구조

```
<작업폴더>/
├── <제목>.pptx          ← 결과물
└── build/               ← new_deck.py 가 kit/ 를 복사해 만든다
    ├── deck.py          ← 내용. 거의 이 파일만 고친다
    ├── layouts.py       ← 표지·목차·간지·맺음·숫자 요약·조직도·앱/웹 화면 자리
    ├── theme.py         ← 색·여백·header/footer/pill/card/table/stat 부품
    ├── engine.py        ← pptx + 미리보기 HTML 생성 (고치지 않음)
    ├── illustrations.py ← 삽화 정의 (빌드 때 PNG 로 자동 생성)
    ├── icons.py         ← 선 아이콘 목록
    ├── build.py / check_fit.py / render.mjs / list_icons.py
    ├── brand_color.py   ← 다른 회사·병원 로고에서 CI 색 뽑기
    ├── assets/          ← 배경·사진 (사진은 여기에 넣는다)
    │   └── logos/       ← 도우·서비스 로고 SVG (빌드 때 PNG 로 자동 변환)
    └── preview/         ← index.html, png/slide-NN.png
```

## 진행 순서

### 1. 재료 모으기
사용자가 준 문서·이미지·메모를 먼저 끝까지 읽습니다. 아래 중 모르는 것만 한 번에 묻습니다(이미 알면 묻지 않음).
- 어떤 자리인지(행사명·날짜), 누가 보는지, 발표 시간 또는 장 수
- 결과 파일을 둘 폴더 (말이 없으면 현재 프로젝트의 `docs/발표자료/`)

### 2. 장 목록 먼저 합의하기
바로 만들지 말고, 아래 표로 장 구성을 보여주고 확인받습니다. 화면 구조를 정하는 일은 사용자의 결정이기 때문입니다.
다만 아래 경우는 확인 없이 바로 만들고, 보고할 때 장 구성을 함께 알려 줍니다.
- 사용자가 장 수와 장마다 담을 내용을 이미 정해 준 경우 ("3장만, 첫 장은 흐름, 둘째 장은…")
- 3장 이하의 짧은 요청
- 사용자에게 물을 수 없는 상황(자동 실행 등) — 합리적으로 정하고 보고서에 선택 이유를 적습니다

| # | 장 제목 | 이 장에서 할 말 한 줄 | 배치 |
|---|---|---|---|
| 1 | 표지 | — | 표지 |
| 2 | 발표 순서 | — | 목차 |
| 3 | … | … | 왼쪽 강조 카드 + 항목 3개 |

원칙 — 기술평가회 발표자료를 만들며 여러 번 되돌리며 확정된 것들입니다:
- **한 장에 메시지 하나.** 부제 한 문장이 그 장의 결론입니다.
- 숫자가 있으면 크게 보여 줍니다(`stat`, `stat_row`).
- 빽빽한 표·카드 격자로 한 장을 꽉 채우지 않습니다. 넘치면 장을 나눕니다. 단, 사용자가 "한 장에 꽉 차도 돼"처럼 밀도를 직접 정하면 그 요청이 우선입니다 — 그때는 recipes.md 9번(내용이 많은 장)을 따릅니다.
- 목차·간지: 섹션이 4개 이상이거나 15장 이상이면 목차 + 섹션마다 간지. 10장 안팎의 짧은 자료는 간지를 빼고, 목차도 표지 부제("회사 소개 · 제품 · 팀")로 대신할 수 있습니다.
- 표지 아래 띠에는 `meta` 3칸(일시·장소·발표자 등)을 꼭 채웁니다. 비면 띠가 허전합니다. 날짜·장소를 모르면 물어보고, 정해지지 않았으면 이미 받은 사실(제품·팀·대상)로 채웁니다.
- 원본 내용이 얇은 칸(한 줄 설명뿐인 제품 등)은 지어내 채우지 말고 레이아웃을 줄이거나 받은 사실로 채웁니다.
- 원본 자료에 없는 사실·숫자를 지어내지 않습니다. 제가 새로 쓴 문장(부제 등)은 보고할 때 알려 줍니다.
- 짧은 요청(예: "조직도 한 장", "흐름 3장만")은 표지·목차 없이 요청한 장만 만듭니다.
- 쓰지 않는 견본(`deck.py` 의 예시 장, `illustrations.py` 의 견본 그림)은 `BUILD`·`ILLUSTRATIONS` 에서 빼고 시작합니다.

### 3. 작업 폴더 만들기
```bash
python3 <이 스킬 폴더>/scripts/new_deck.py <작업폴더>
```
`<이 스킬 폴더>`는 이 SKILL.md 가 있는 폴더입니다(설치 방식에 따라 `~/.claude/skills/dou-ppt-design` 또는 `~/.agents/skills/dou-ppt-design` 등). 엔진을 복사하고 python-pptx·playwright를 설치합니다. 이미 `build/deck.py`가 있으면 새로 만들지 말고 그 파일을 고칩니다.
node가 없으면 `brew install node`를 안내합니다(아이콘·미리보기 이미지에 필요).

### 4. deck.py 채우기
- 맨 위 `TITLE`(파일 이름), `theme.FOOT`(모든 장 아래 한 줄), `SECTIONS`를 정합니다.
- 장마다 함수 하나, 마지막에 `BUILD = [...]` 순서대로 나열합니다.
- 표지·목차·간지·맺음·숫자 요약·조직도는 `layouts.py` 함수를 씁니다.
- 쓸 수 있는 아이콘 이름은 `python3 list_icons.py` 로 확인합니다.
- 본문 배치는 **references/recipes.md** 를 읽고 맞는 레시피를 골라 복사합니다. 없는 배치가 필요하면 같은 부품(`card`, `pill`, `icon_badge`, `table`, `stat`)과 같은 여백(`MX`=64, 카드 간격 16~28, 둥근 모서리 10~16)으로 조합합니다.
- **색**: 도우 쪽 내용·강조는 `PRIMARY`(dou-design-system blue-500, #3B82F6)와 그 계열(`PRIMARY_DK` blue-600, `TINT` blue-50, `TINT2` blue-100)만 씁니다. 다른 파란색을 새로 만들지 않습니다.
- **도우·서비스 로고**: `logo("새록", x, y, 높이)` 처럼 이름만 적으면 들어갑니다(도우·새록·미리봄·약먹자·수발(실마리라고도 부름)). 짙은 바탕에는 `white=True`. 폭은 원본 비율로 자동 계산되며 `logo_width(이름, 높이)` 로 미리 알 수 있습니다. 로고를 늘이거나 색을 바꾸지 않습니다. 새 서비스 로고는 SVG 를 `assets/logos/` 에 넣고 `layouts.LOGO_ALIAS` 에 별칭을 추가합니다.
- **다른 회사·병원이 나올 때**: 그 기관 내용은 그 기관 CI 색으로 구분합니다(도우 = blue-500, 상대 기관 = 그 기관 색).
  1. 로고 파일을 받습니다. 없으면 사용자에게 요청합니다(웹에서 임의로 받아 쓰지 않음 — 공식 파일인지 확인할 수 없어서).
  2. `build/assets/` 에 넣고 `python3 brand_color.py assets/<로고파일>` → 대표색과 `brand("#색")` 결과가 나옵니다. 그라디언트 로고처럼 후보가 여러 개면 더 짙고 넓게 쓰인 색을 고르고, 무채색 로고면 사용자에게 CI 색을 묻습니다.
  3. deck.py 위쪽에 `HOSP, HOSP_TEXT, HOSP_T = brand("#색")` 처럼 세 벌을 만들어 씁니다. 채움(막대·점·로고 옆 선)은 첫째, **글자는 둘째(흰 바탕 대비 확보)**, 옅은 배경은 셋째.
  4. 그 기관 색은 그 기관을 가리키는 곳(이름, 담당 표시, 구분 막대)에만 쓰고, 장 전체 강조색은 도우 blue-500 을 유지합니다. 레시피는 recipes.md 11번.
- **표**: `theme.table(...)` 을 씁니다. 칸마다 파워포인트에서 바로 고칠 수 있는 글상자로 들어갑니다. 레시피는 recipes.md 4번.
- **앱·웹 화면**: 캡처가 들어갈 장은 recipes.md 10번(`app_flow` 흐름, `app_callouts` 화면 설명, `phone_slot`·`browser_slot` 자리)을 씁니다. 캡처가 아직 없으면 이미지 없이 만들어 **점선 빈칸에 위치만** 잡고, 보고할 때 "어느 장에 어떤 캡처가 필요한지" 목록을 줍니다. 캡처를 받으면 `assets/`에 넣고 `image=` 에 파일명만 넣어 다시 빌드합니다. 앱 화면을 그림으로 지어내 그리지 않습니다.
- **삽화**: 사진이 없는데 그림이 있으면 이해가 빨라지는 장(문제 상황, 전후 비교, 제품 화면, 지도)은 `illustrations.py` 에 그림을 그려 넣습니다. 방법·스타일·견본은 **references/illustrations.md** 를 읽습니다. 사람·사실적 장면은 그리지 않고 사진을 요청하거나 아이콘 카드로 대신합니다.
- 장마다 `s.notes = "..."`에 발표자가 실제로 말할 2~3문장을 넣으면 파워포인트 발표자 노트로 들어갑니다(요청이 있거나 발표용일 때).

### 5. 빌드하고 눈으로 확인하기
```bash
cd <작업폴더>/build
python3 build.py            # <제목>.pptx + preview/index.html
python3 check_fit.py        # 글이 상자를 넘치는 곳
node render.mjs preview     # preview/png/slide-NN.png
```
- `check_fit.py`가 "넘침 없음"이 될 때까지 고칩니다.
- **png를 직접 열어 모든 장을 봅니다.** 겹침, 잘린 글자, 한쪽으로 쏠린 배치, 너무 빈 아래쪽을 찾아 고치고 다시 빌드합니다. 확인 안 한 장을 "완료"라고 하지 않습니다.
- 파워포인트에서 글꼴이 다르게 보일까 걱정되면 글꼴을 파일에 심습니다. 저장소 용량 때문에 글꼴은 들어 있지 않아서, [Noto Sans KR](https://fonts.google.com/noto/specimen/Noto+Sans+KR) 400·700 굵기 TTF 를 `build/fonts/NotoSansKR-400.ttf`, `NotoSansKR-700.ttf` 로 넣고 `pip install fonttools` 후 `EMBED_FONT=1 python3 build.py`. 구글 슬라이드는 Noto Sans KR을 이미 갖고 있어 필요 없습니다.

### 6. 전달하기
짧게 보고하고, 표로 어디를 봐야 하는지 알려 준 뒤 직접 띄워 줍니다.

| 화면 | 위치 | 볼 것 |
|---|---|---|
| 발표자료 N장 | **<작업폴더>/<제목>.pptx** | 전체 흐름 |

```bash
open "<작업폴더>/build/preview/index.html"   # 미리보기
open -R "<작업폴더>/<제목>.pptx"             # Finder 에서 파일 선택
```
파워포인트·키노트가 없는 컴퓨터가 많아 `.pptx`를 `open`으로 바로 열면 실패할 수 있습니다. 그래서 Finder에서 선택해 보여주고, 구글 슬라이드에 올려 보라고 안내합니다.

## 고치기 요청을 받았을 때
"점이 어색해", "이 사람만 강조하지 마" 같은 피드백은 해당 장 함수만 고치고 다시 빌드 → 해당 장 png 확인 → 보고합니다.
같은 피드백이 공통 부품(`layouts.py`)에 해당하면 그 함수를 고쳐 모든 장에 반영합니다.
